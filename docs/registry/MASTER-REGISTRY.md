## 7. Repository policy

The strategic entity model does not imply automatic repository creation.

A separate repository requires documented justification based on one or more independent boundaries:

- development lifecycle;
- ownership/stewardship;
- security or data;
- deployment;
- access control;
- versioning/release;
- issue/project management;
- contributor/community boundary.

Until those criteria are met and the Master Registry records approval, the entity remains a project, product, service, module, protocol, domain or concept within the existing architecture.

## 8. Current GitHub reality

The connected GitHub account currently confirms **WisdomPact** as the existing repository.

The other strategic entities are not represented here as existing repositories unless and until they are explicitly created and confirmed.

The intended architecture therefore remains:

**WisdomPact → WisdomIntercessor.com project + Eternal Wisdom Foundation organization + strategic domains/services/products**

rather than:

**Every named ecosystem component → separate repository.**

## 9. Rule

Do not create a document, project, organization, product, service, module, or repository merely to fill a directory or satisfy a numerical target.

Each new entity must have a defined purpose, type, owner/stewardship model, scope, status, and relationship to the existing architecture.
